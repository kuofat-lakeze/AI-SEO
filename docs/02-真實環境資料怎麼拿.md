# 02・真實環境資料怎麼拿

模擬環境裡 `generate_logs.py` 做的事，在真實客戶那裡是「把 log 要過來」。這份文件講每一列資料在真實世界的來源、怎麼接、會踩到什麼坑。

## 資料來源總表

| 圖上的列 | 真實來源 | 取得方式 | 更新頻率 |
|---|---|---|---|
| SEO / LLMO / GEO / AEO 各種爬蟲 | **網站伺服器 access log** | nginx / Apache 的 log 檔，或 CDN（Cloudflare、AWS CloudFront、Akamai）的 log 匯出 | 每天 |
| 自然流量（真人） | GA4 / Matomo，或同一份 log 的 Referer | GA4 的「流量獲取」報表 `Session source` 可直接分出 chatgpt.com、perplexity.ai | 每天 |
| 自然流量的搜尋細節 | Google Search Console、Bing Webmaster Tools | API 或後台匯出；曝光、點擊、查詢字 | 每天（有 2 天延遲） |
| MEO | Google Business Profile（商家檔案） | 後台「成效」或 Business Profile Performance API：曝光、路線查詢、來電、網站點擊 | 每天 |
| AI 引用（有沒有被 AI 答案提到） | 自己定期問 AI | 用固定的一組問題，每週對 ChatGPT / Perplexity / Gemini 跑一次，記錄有沒有引用客戶網址 | 每週 |

## 伺服器 log：最重要的一份

### 要求客戶提供什麼

- nginx：`/var/log/nginx/access.log*`（含 rotate 過的 `.gz`）
- Apache：`/var/log/apache2/access.log*`
- 格式至少是 **combined**（含 Referer 與 User-Agent）。`templates/nginx-log-format.conf` 有建議格式，多加 `$http_cf_connecting_ip` 等欄位更好

拿到以後直接用這個 repo 的分類器：

```bash
zcat -f /path/to/access.log* > client.log          # 把多個檔合併
python3 lab/classify.py client.log --label 客戶A-9月 --out output/clientA-09.json
python3 lab/report.py output/clientA-09.json --out output/clientA-09.html
```

### 客戶用 Cloudflare 時

很多企業網站在 Cloudflare 後面，原站 log 可能只看到 Cloudflare 的 IP，而且**被 Cloudflare 擋掉的爬蟲根本不會到原站**。兩個選擇：

1. **Cloudflare Logpush**（付費方案）：把 HTTP request log 推到 S3 / R2，欄位含 `ClientRequestUserAgent`、`ClientRequestReferer`、`EdgeResponseStatus`。寫個小轉換把它變成 combined 格式，就能餵給 `classify.py`
2. **Cloudflare 的 AI Audit / Bot Analytics**：後台直接有各 AI 爬蟲的請求數，可以手抄或用 GraphQL API 拉。好處是連被擋的都看得到

Cloudflare 2024 年起預設提供「一鍵封鎖 AI 爬蟲」，**很多客戶不知道自己已經擋掉了**。這常常是第一個發現、也是第一個可以量化的改善。

### 其他主機環境

| 環境 | 怎麼拿 |
|---|---|
| WordPress 虛擬主機（cPanel） | cPanel → 原始存取記錄（Raw Access Logs）下載 |
| Vercel / Netlify | Log Drains 導到外部服務，或付費方案的 log 匯出 |
| AWS CloudFront | Standard logging 到 S3，欄位含 `cs(User-Agent)`、`cs(Referer)` |
| Shopify 等 SaaS | 拿不到伺服器 log，只能靠 GA4 + Cloudflare（若有） + 人工 AI 查詢 |

## 爬蟲驗證：別被假的騙

任何人都可以把 User-Agent 改成 `Googlebot`。給客戶的報告如果要經得起質疑，至少做到：

1. **官方 IP 清單比對**：Google、OpenAI、Anthropic、Bing、Apple、Perplexity 都公布爬蟲 IP 範圍（JSON）。把 log 的 IP 對清單，不在範圍內的標成「偽裝」
2. **反查 DNS**：Googlebot 的 IP 反查應該是 `*.googlebot.com` 或 `*.google.com`，再正查回去要一致
3. 偽裝的那些歸到「自動瀏覽 / 可疑」，不要算進 SEO

`classify.py` 目前沒做 IP 驗證（模擬 IP 是亂數），真實專案建議加一層。

## 自然流量裡的 AI 導流

GA4 裡看 **報表 → 流量獲取 → 工作階段來源**，篩 `chatgpt.com`、`perplexity.ai`、`copilot.microsoft.com`、`gemini.google.com`、`claude.ai`。
建議做一個自訂管道群組「AI Referral」把它們合起來，這就是儀表板「AI 導流」表的真實來源。

注意：

- ChatGPT 的連結有時帶 `utm_source=chatgpt.com`，GA4 會自動歸類
- 有些 AI 平台的點擊不帶 Referer，會掉進「直接流量」，所以 AI 導流通常是**低估**
- 真實 log 的 Referer 也能分，`bots.json` 的 `referrers` 區塊就是做這件事

## 常見坑

- **log 只留 7 天**：很多主機預設就 rotate 掉。第一次接觸客戶就要先把 log 保留期拉長到 90 天以上，不然沒有「優化前」可以比
- **時區**：log 時間通常是伺服器時區，GA4 是帳戶時區，對日期時要注意
- **爬蟲數量不等於成效**：ClaudeBot 來 2,000 萬次不代表 Claude 會推薦客戶，只代表內容被讀過。報告裡要把「被讀到」與「被引用」分開講（見 03）
- **404 與 403**：爬蟲一直抓 404 的舊網址代表站內連結有問題；403 代表被擋。儀表板有列出 403，這兩個都是容易量化、容易修的項目
