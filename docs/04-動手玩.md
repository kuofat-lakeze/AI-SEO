# 04・動手玩

幾個可以在這個 lab 裡直接做的實驗，每個都對應一個真實專案會遇到的情境。

## 實驗 1：跑一次完整流程

```bash
./run.sh
```

打開 `output/dashboard.html`。對照原圖看四列的對應關係。

## 實驗 2：客戶把所有 AI 爬蟲都擋了

模擬 Cloudflare 一鍵封鎖的狀況。改 `lab/generate_logs.py` 的 `SCENARIOS["baseline"]["blocked_bots"]`：

```python
"blocked_bots": {"GPTBot", "ClaudeBot", "OAI-SearchBot", "ChatGPT-User", "PerplexityBot", "Bytespider", "CCBot"},
```

再跑 `./run.sh`。看「被阻擋（403）的爬蟲」表，以及優化後 AEO 的變化百分比會變多大。這就是健檢最常見的第一個發現。

## 實驗 3：加一隻新爬蟲

AI 爬蟲每個月都有新的。在 `lab/bots.json` 的 `bots` 陣列加一筆，例如：

```json
{"match": "NewAIBot", "platform": "NewAI", "name": "NewAIBot", "domain": "geo", "weight": 50000,
 "ua": "Mozilla/5.0 (compatible; NewAIBot/1.0; +https://example.com/bot)"}
```

重新跑，GEO 的「來訪者種類」會多一家。真實專案裡，維護這張表就是你的 know-how。

## 實驗 4：餵真實的 log

如果手上有任何網站的 nginx / Apache log：

```bash
python3 lab/classify.py /path/to/access.log* --label 真實 --out output/real.json
python3 lab/report.py output/real.json --out output/real.html
```

看 `unknown` 有多少。那些是對照表還不認識的 User-Agent，用下面的指令找出最常見的：

```bash
awk -F'"' '{print $6}' /path/to/access.log | sort | uniq -c | sort -rn | head -50
```

把該分類的加進 `bots.json`。

## 實驗 5：改變優化幅度

`SCENARIOS["optimized"]` 裡的倍率可以改。試著把 `aeo_fetch` 改成 1.0、`ai` 導流改成 1.0，看一份「爬蟲變多但沒有導流」的報告長什麼樣。這就是「只做到被讀到、沒做到被引用」的案例，提案時要能分辨。

## 實驗 6：把規模調到跟原圖一樣

原圖是七個月的資料。`bots.json` 的 `weight` 就是依原圖的數量級設定的，所以：

```bash
./run.sh 220 1.0
```

會產生接近原圖量級（數千萬行）的 log，但檔案會有十幾 GB，一般筆電不建議。用 `./run.sh 220 0.01` 看趨勢就夠了。
