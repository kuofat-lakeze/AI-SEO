# 06・做一個包棟訂房平台，要讓 AI 引用：怎麼進行

前提是 05 的基準快照：AI 回答「宜蘭包棟」時引用的是整理站與媒體，不是民宿官網。
一個包棟訂房平台在結構上就是 AI 會引用的那種網站，但目前那些整理站的文章都是「列表加形容詞」，沒有一家提供結構化、可比較、會更新的資料。**這就是切入點：做成 AI 最省力的那份資料來源，而不是第 N 篇推薦文。**

## 核心原則：AI 引用的是「欄位」，不是「文章」

回頭看 AI 的回答長什麼樣：

> 135會館（冬山）包棟最多 20 人，有卡拉OK、麻將桌、超大游泳池。羽楓左岸（五結）10 人一晚 52,800 元。8 至 10 人平日約 8,000 至 10,000 元，假日約 14,000 至 15,000 元。

每一句都是 **地區 × 人數 × 設施 × 價格 × 距離** 這五個欄位的組合。平台要做的，就是讓每一間民宿、每一個主題頁都把這五個欄位講得比任何人清楚、而且是最新的。

## 一、資料層：每間民宿一張「事實表」

每個民宿頁都要有同一套欄位，由平台驗證、定期更新，不是讓民宿自己寫形容詞：

| 欄位 | 範例 | 為什麼 AI 需要 |
|---|---|---|
| 人數 | 基本 10 人，最多 16 人，加人費 800 元 | 「12 人包棟」這種問法 |
| 房數與床型 | 5 房，2 雙人 3 四人 | 分房需求 |
| 價格 | 平日 12,000・週六 18,000・連假 22,000・春節 26,000 | 「多少錢」是最常見的交易型問題 |
| 設施 | 泳池（戶外、5 到 10 月）、KTV、電動麻將 2 桌、烤肉區（代訂食材）、寵物可 | 「有泳池的」「可帶寵物」 |
| 位置 | 冬山鄉，距羅東夜市車程 10 分鐘，距傳藝中心 8 分鐘 | AI 回答一定帶「距離羅東夜市 X 分鐘」 |
| 適合對象 | 公司團體、親子、朋友聚會 | 意圖型問題 |
| 評價 | 平台評分、則數、最新評論日期 | 可信度與新鮮度 |
| 可訂日期 | 即時空房 | 其他整理站沒有的獨家資料 |

技術上對應：

- 每頁一份 JSON-LD：`LodgingBusiness`（或 `VacationRental`）+ `Offer`（含價格區間）+ `AggregateRating` + `amenityFeature` + `geo`
- 主題頁用 `ItemList` 列出比較結果
- 每頁都有 `FAQPage`，問題就是使用者會問 AI 的話（「可以帶寵物嗎」「平日幾點入住」）
- 頁面上同一份資料用 **表格** 呈現，不要藏在圖片或輪播裡

## 二、頁面架構：對準人問 AI 的方式

人不會問「宜蘭包棟」四個字就結束，會加條件。平台的頁面樹就照條件長：

```
/宜蘭包棟/                        總覽 + 價格行情 + 地區比較
/宜蘭包棟/冬山/  /礁溪/  /五結/   地區頁：該區民宿比較表 + 該區特色（礁溪有溫泉、冬山近夜市）
/宜蘭包棟/10人/  /15人/  /20人/   人數頁：剛好容納該人數的民宿 + 每人均價
/宜蘭包棟/泳池/  /KTV/  /寵物/  /烤肉/   設施頁
/宜蘭包棟/公司旅遊/  /親子/  /朋友聚會/    情境頁
/宜蘭包棟/價格/                   價格行情頁（見下，最重要的一頁）
/民宿/<名稱>/                     事實表頁
```

每個主題頁的結構固定：一句話結論 → 比較表 → 怎麼選的三條建議 → FAQ → 民宿清單。AI 摘要最常抓的就是「一句話結論 + 表格」。

## 三、獨家資料：讓平台成為「唯一來源」

整理站之所以被引用，是因為 AI 找不到更好的。平台有訂房資料，可以產出別人做不出來的東西：

1. **價格行情頁**：用平台真實成交或掛牌價，按地區、人數、平假日算出中位數與區間，每月更新並標日期。這一頁會取代 uptogo 那篇「包棟民宿多少錢」被引用。
2. **季節報告**：「2026 宜蘭包棟價格與熱門設施報告」，每季一篇，有數字、有圖表、有方法說明。媒體會引用報告，AI 會引用媒體與報告本身。
3. **空房與旺季指標**：「本週末冬山包棟剩餘空房 3 間」這類即時資料，是 Agent 時代最會被查的東西。

原則：**有日期、有數字、有方法、會更新**。沒有這四樣的內容，AI 只會當成另一篇推薦文。

## 四、技術層：確保 AI 抓得到、讀得懂

- **robots.txt**：放行 OAI-SearchBot、ChatGPT-User、PerplexityBot、Perplexity-User、Claude-SearchBot、Claude-User、Applebot、Googlebot、Bingbot。訓練爬蟲（GPTBot、ClaudeBot）建議也放行，平台要的是被模型「記得」。範本在 `templates/robots.txt`
- **不要只靠 JavaScript 渲染**：很多 AI 即時抓取不執行 JS。民宿頁與主題頁要 SSR 或靜態輸出，表格與價格要在 HTML 裡
- **llms.txt**：列出主題頁與價格行情頁，一句話說明每頁有什麼。範本在 `templates/llms.txt`
- **sitemap 的 lastmod 要真**：價格更新就改 lastmod，AI 搜尋引擎重抓有依據
- **穩定的 URL 與 canonical**：同一間民宿不要多個網址
- **速度**：AI 抓取有逾時，首屏 HTML 要小
- **Cloudflare**：關掉「封鎖 AI 爬蟲」，但保留速率限制

## 五、站外：讓 AI 在別的地方也看到你

AI 判斷一個來源可不可信，看的是它在其他地方被怎麼提到：

1. **被現有的整理站與媒體引用**：帶著價格報告去找食尚玩家、yam、FunTime，提供他們沒有的數字。AI 引用媒體、媒體引用你，兩層都算
2. **社群討論**：ChatGPT 與 Perplexity 很重視論壇。Dcard、PTT、Mobile01 的包棟討論串裡要有平台的自然出現，不是廣告
3. **品牌實體一致**：平台的 Google 商家檔案、社群帳號、新聞稿、合作民宿頁面上的名稱與描述要一致，AI 才會把它們視為同一個實體
4. **民宿端的回連**：合作民宿官網放「在 XX 平台訂房」的連結，這是最自然的反向連結

## 六、量測：三層指標，從第一天開始收

| 層 | 工具 | 指標 | 預期時程 |
|---|---|---|---|
| 被讀到 | `lab/classify.py` 跑平台 log | GEO / AEO 爬蟲造訪次數、抓的頁面 | 上線後 2 到 4 週 |
| 被引用 | `lab/citation_check.py` 跑題庫 | 提及率、引用率、聲量佔比、來源結構 | 提及 1 到 3 個月，引用 3 到 6 個月 |
| 被點擊 | GA4 AI 導流 | 來自 chatgpt.com / perplexity.ai 的工作階段與訂房轉換 | 跟著引用率走 |

題庫先用 `lab/queries/宜蘭包棟.json`，把 `target` 改成平台的名稱與網域，每週固定跑。基準是今天的 0%。

## 七、進行順序

**第 0 到 1 個月：資料與結構**
- 簽 30 到 50 間民宿，每間做完事實表，欄位齊全
- 主題頁樹上線，每頁有表格與 FAQ，JSON-LD 齊全
- robots、llms.txt、sitemap、SSR 確認
- 開始收 log，跑第一次題庫（基準）

**第 1 到 3 個月：獨家資料與站外**
- 價格行情頁上線，每月更新
- 第一份季度報告，拿去找媒體
- Dcard / PTT 出現
- 每週題庫，預期先看到「提及」

**第 3 到 6 個月：Agent 與規模**
- 開放結構化資料 API 或 MCP 伺服器，讓 AI Agent 能查空房與價格（AAIO）
- 擴到其他縣市的包棟，用同一套頁面樹
- 預期看到「引用」與 AI 導流

## 會失敗的做法

- 民宿頁只放民宿自己寫的介紹文：跟整理站一樣，沒有理由被引用
- 價格寫「請來電洽詢」：AI 直接跳過你，去引用有數字的整理站
- 全站 JS 渲染、資料靠 API 動態載入：AI 抓到的是空頁
- 擋掉所有爬蟲再問為什麼沒被引用
- 一開始就鋪全台：資料不深，每個地區都輸給在地整理站。先把宜蘭做到被引用，再複製
